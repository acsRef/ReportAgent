# Agent 项目测试流程：正规性评估 + 可迁移经验

> 面向读者：我自己（三个月后还要按这套跑）和任何要接手的 agent 项目。
> 结论先给：**这套流程在"分层 / 契约 / 确定性 / 证据分级"上是正规的；在"依赖与环境纪律 / flaky 治理 / 可复现性"上不正规**。
> 最后给一份可以整包复制到新项目的脚手架：`docs/templates/agent-testing/`（pytest marker 约定、env-gate conftest、L2 workflow 模板、prompt 行为用例 schema、一页检查表）。

## 二、正规性评估：10 个维度逐条判

判定口径：**✅ 达标**（有明确做法且能持续跑）｜**⚠️ 部分**（做了但不成体系）｜**❌ 缺口**（没有或无效）。

| # | 维度 | 行业标准做法 | 本仓现状 | 判定 |
|---|---|---|---|---|
| 1 | **分层（测试金字塔变形）** | 底层多、上层少；agent 项目里"契约"应比单元更重 | 契约 97 个文件是主体，图/持久化次之，e2e 仅 5 个且不入 push 门禁——方向对 | ✅ |
| 2 | **确定性（离线可复算）** | 离线套件不碰网络/真 LLM；判定器是纯函数 | `PHASE2_MCP_ONLY` 锁 MCP、`REPORTAGENT_E2E` gate 真链路、判据全确定性、不引入 LLM 裁判做门禁 | ✅ |
| 3 | **契约测试** | 工具 description / 状态 schema / SSE 事件面 / 前端 reducer 都有钉子 | 97 个契约文件；`test_legacy_import_freeze`、`test_tool_descriptions`、SSE 七事件、`analysisReducer` | ✅ |
| 4 | **门禁 vs 信号分离** | push 门禁快且稳；慢/贵的进夜间，失败要报警 | L1 3 job（2–3 min）；L2 夜间 + 手动；**本轮之前夜间连红 7 天无人知**，现已加自动 Issue | ⚠️→✅ |
| 5 | **真链路测试** | 真 LLM/真检索/真 DB 必须存在，但**不拦每次提交** | L2 core（prompt 行为 + 压缩保真）+ full（真 RAG 链路，每周）；证据档位标注 | ⚠️→✅（远端 dispatch 待验证） |
| 6 | **prompt 质量** | 测行为、不测文案；概率性用多采样；每例写清"什么改动会让它红" | 已有 13 例行为集（`breaks_when` 准入 + 3 采样取多数）；但历史 ≈78 处文案断言**仍在** | ⚠️ |
| 7 | **测试资产治理** | 用例/金标/夹具都有来源、版本、重挂机制；夹具与契约同步有闸 | 金标 `rag_doc_map.json` 重挂表、评测平台证据档位、**新增 fixture 防漂移闸** | ✅ |
| 8 | **依赖与环境纪律** | 依赖 pin、干净环境可重建；"本地绿 ≠ CI 绿"要当成信号 | 本轮才钉住 `SQLAlchemy<2.1` / `bcrypt==4.0.1`；此前 ragent 仓零 CI、靠本地碰巧装的旧版本 | ❌→✅（刚补） |
| 9 | **可复现性** | 一条命令在任何 cwd 给出同样结果 | 同一条 `pytest` 在 repo root 收集 1937 例、在 `backend/` 下出现 3 个收集错误（3 个文件 `import evaluation`）——**结果依赖 cwd**；已在 `backend/tests/conftest.py` 把 repo root 放进 `sys.path` 修好，两处都 1937 | ✅（当日修） |
| 10 | **flaky 治理** | 有隔离名单/重跑策略/统计 | 无；真链路靠"多采样取多数"缓解，但没有 quarantine 机制与失败率统计 | ❌ |

## 三、可迁移经验：Agent 项目测试「四层 + 六纪律」

### 3.1 一个公式

```
可交付的测试价值
 = 契约覆盖（确定性） × 真链路段位（真实性） × 判定器可信度 × 失败可见性 × 迭代速度
```

任何一项接近 0，整体就接近 0：
- 契约全绿但没真链路 → 只能证明"以前修过的坑没复发"（本仓 11-18 之前的真实状态）；
- 有真链路但判定器算错 → 看到的是假失败（本仓 8 条 fail 里 4 条是阈值 `0.67` 够不到 `2/3`）；
- 都对了但红了没人看 → 等于没有（夜间连红 7 天）。

### 3.2 四层（每层只答一个问题）

| 层 | 频率 | 跑什么 | 不该测什么 | 成本 | 失败含义 |
|---|---|---|---|---|---|
| **L1 契约/单元** | 每次 push | 纯函数、schema、工具 description、SSE 事件面、状态迁移、reducer | 真模型输出、检索质量、真实耗时 | 秒级 | 代码/契约被改坏 |
| **L2 真链路** | 每晚 + 手动 | 真 LLM 端到端、真检索、真 DB、压缩保真 | 全量回归（放最后跑） | 分钟级，需 key | 行为退化（要人判断） |
| **L3 质量回归** | 每周/里程碑 | golden set 打分、评测平台、场景测试 | 每次提交（太贵） | 十分级 + 额度 | 质量趋势变化 |
| **L4 发布卡口** | 打 tag 前 | 要求 L2 最近一次绿 + 关键场景结论 | 新写用例 | 0 | 敢不敢发 |

**顺序纪律**：同一条流水线里，**贵而值的先跑、普通回归最后跑**（本仓 `offline-regression` 用 `needs` 排在真链路之后，`if: always()`）。这样红的时候先看到的是"哪一层坏了"，而不是被 1900 个测试的噪音淹没。

### 3.3 六条纪律（每条都带本仓证据）

1. **判定器先自证**：阈值与文案同源（写 `2/3` 不写 `0.67`）；每类判据有"恰好等于边界"的用例；报缺陷前先看 `expected/observed`。
   *证据*：8 条 fail 里 4 条是判定器阈值算错。
2. **prompt 只测行为**：断言闭集枚举/集合包含/归一相等，不断言文案；每例必须写 `breaks_when`；概率性用 **N 采样取多数**（本仓 N=3）。
   *证据*：13 例里 2 例单次采样会抽风（占比→ranking、打招呼→分析任务），3 采样后稳定。
3. **真链路不进门禁、但必须存在**：缺 secret 时 **skip 并打印 warning**，不要红（红了会训练人无视 CI），也不要假装通过。
4. **资产有版本**：gold id / 夹具 / 语料都会漂；维护"重挂表"，并给夹具加**防漂移闸**（用与生产同一条判定函数）。
   *证据*：三份年报重入库 4 次，document_id 变了 4 次；夜间连红的根因就是夹具没跟上新契约。
5. **失败要能吵醒人**：定时失败自动开/更新 Issue（同标题去重）；手动触发失败不刷 Issue（调试噪音）。
6. **依赖必须 pin、环境必须干净重建**：「本地绿」不是证据。
   *证据*：`SQLAlchemy` 未 pin → CI 装到 2.1 把默认驱动换成 psycopg v3 → 21 个测试收集失败；`bcrypt 5.0` 与 `passlib 1.7.4` 不兼容 → passlib 直接抛错。两者本地都绿，因为本地是旧版本。

### 3.4 反模式清单（都是本仓真踩过的）

| 反模式 | 症状 | 后果 | 正解 |
|---|---|---|---|
| 用 mock 冒充真链路 | 1900 例全绿，改 prompt 也绿 | 假绿 | 分层 + 每晚真链路 |
| 断 prompt 文案 | 改一个字就红 | 假红 → 人开始无视 CI | 行为集替代文案断言 |
| 同一条断言既想测版本又想测行为 | 文案变就红，行为变不一定红 | 信号错位 | 行为集 + 资产版本分开 |
| 定时任务失败不报警 | 连红 7 天没人看 | 流水线等于不存在 | Issue 自动开 |
| 未 pin 依赖 | 本地绿/CI 红反复横跳 | 排查成本 >> 修复成本 | pin 主版本 + 干净环境验证 |
| 判定器阈值手抄小数 | `0.67` vs `2/3` | 及格判成不及格 | 真分数 + 边界用例 |
| 把 `deferred` 当 pass | 页面全绿但一层没测 | 结论不可信 | deferred 单独计数 |
| 一次采样定生死（LLM 行为） | 同一用例跑两次一绿一红 | 噪音淹没真信号 | 多采样取多数 |

## 四、7 天上手节奏（新 agent 项目直接照抄）

| 天 | 做什么 | 完成标志 |
|---|---|---|
| **D0（2h）** | 三件套：`pytest.ini` marker 约定、`ci.yml`（后端 + 前端 + 契约门禁）、依赖 pin | push 触发，3–5 min 内出结论 |
| **D1（4h）** | 契约层先写：工具 description、状态 schema、SSE/事件面、前端 reducer | 契约红能定位到具体契约条款 |
| **D2（4h）** | 隔离纪律：离线套件禁网络（sentinel 环境变量）、真 LLM 用 env-gate、缺 key 时 skip | 拔网线仍能跑离线套件 |
| **D3（4h）** | L2 骨架：`live-eval.yml`（nightly + dispatch）、真链路最小 3 条、失败自动开 Issue | 手动 dispatch 跑通、并有 artifact |
| **D4（4h）** | prompt 行为集（10–15 例）：`enum_exact` / `set_contains` / `normalized_eq` / `numeric_grounded`；每例带 `breaks_when`；3 采样取多数 | 抽掉一句关键 prompt 说明，能红 |
| **D5（4h）** | 资产治理：gold/夹具来源+版本登记、重挂表、夹具防漂移闸 | 故意改坏夹具会先在 L1 红 |
| **D6（2h）** | 成本与顺序：core/weekly 分档、普通回归排最后、artifact/Summary | 夜间跑完有人能看懂结论 |
| **之后每日** | 看一次夜间结论；红了当天下修；每周清一次 flaky | 红线不跨周 |

**成本参考**（本仓实测）：L1 ≈ 2–3 min/次；L2 core ≈ 10 min/晚 + ≈40 次 LLM 调用；L2 full ≈ 20 min/周 + 一次语料重建（5 min）；L3 评测 ≈ 按需。

## 五、一页检查表（复制到新项目 README）

```markdown
### 测试门禁检查表
- [ ] 一条命令从 repo root 跑全量；任何 cwd 结果一致
- [ ] 离线套件不碰网络/真 LLM（有 sentinel 断言）
- [ ] 依赖 pin 住主版本；干净环境（容器）能重建
- [ ] 契约层覆盖：工具描述 / 状态 schema / 事件面 / 前端 reducer
- [ ] 真 LLM 用例 env-gate；缺 secret 时 skip + warning（不红、不假绿）
- [ ] prompt 只测行为；每例有 breaks_when；多采样取多数
- [ ] 判定器有边界用例；阈值不手抄小数
- [ ] 夹具/金标有来源与版本；有防漂移闸；重入库后重建重挂表
- [ ] 定时失败自动开/更新 Issue（去重）；手动失败不刷
- [ ] 证据分层：deferred 不计分；timeout ≠ fail；artifact 可复盘
- [ ] 贵而值的先跑，普通回归最后跑
- [ ] 夜间红线不跨周；flaky 有隔离（不掩盖 push 门禁）
```

## 六、这套经验里「不要照抄」的部分

| 做法 | 为什么本仓可以，别的项目要改 |
|---|---|
| 评测平台单独一个 FastAPI 服务 | 两项目共用同一 PG + 真人维护时划算；单项目直接写 pytest 插件更轻 |
| Playwright Contract E2E 用 mock LLM + 真 PG | 前端重、SSE 复杂才值得；纯后端 agent 别上 Playwright |
| 65 题 golden set 用 XML/JSON 手标 | 语料固定才可行；语料会变就得上"抽样 + 判据"，别维护全量金标 |
| `deferred` 层单独计数 | 我们的"执行/报告"层需要 confirm 才能测；如果你的链路一次性跑完就不需要 |
| 多采样取多数 | 只在**行为闭集**上有效；开放式生成质量仍要靠人评或 golden judge |

# 有合理默认就不要问：口径没提时按注册表默认前进，不再弹选择题

## Context（背景）

用户原话（2026-11-04，连续两轮）：

> 「大模型会识别不出来我的意图？？？我的意图已经很明显了啊」
> 「**不一定总是要给选项啊，这种意图清晰的为什么要给选项**」

实测现场：一句「把最差的那个月的明细给我看看」，卡片已经正确解析出
`detail_level=detail`、`top_period={最低, 月}`，但仍然弹出一道
「用哪个口径？」的选择题（销售额 / 净销售额 / 实收金额）——用户必须先点一下才能继续。
这不是歧义，只是**这句话里没提口径**。

## Design（设计）

把「没提」和「有歧义」分开处理：

| 情况 | 之前 | 现在 |
|---|---|---|
| 用户**这一轮没提口径**（「最差的那个月的明细」） | 弹选项，阻塞 | 按注册表 `default: true` 的口径（销售额）**直接前进**，并在卡上写明 |
| 用户提了**一词多义**的说法（「金额」同时对上多个口径） | 弹选项 | 仍然弹（这次是真的在问词义） |
| 上一轮已确认口径 | 继承（已被物理列名 bug 破坏，同批修掉） | 继承 |

「直接前进」也要可见、可改：
- `assumptions` 里落一条 `metric_default:<口径>` 的**已接受**假设，文案写清
  「默认按「销售额」口径（订单金额口径，未扣退款）；要换口径直接说，例如「净销售额」」；
- 确认条 chip 上标 `销售额（默认口径）`（前端 `confirmChips`）；
- 用户想换：一句话（supplement 通道已存在），或点「需求详情」看明细。

## Files to change（文件改动）

| 文件 | 改动 |
|---|---|
| `backend/app/agent/requirement_parser.py` | `_apply_slot_resolutions`：无明确口径词 + 有注册表默认 → 落默认口径 + 已接受假设，不生成 missing_field |
| `backend/app/services/requirement_service.py` | 澄清选项写回时把物理列名归一成业务名（`order_amount` → 销售额），否则下一轮继承不到 |
| `backend/app/agent/requirement_slots.py` | 继承路径同样做归一（旧卡兼容） |
| `frontend/src/components/workbench/slotQuestion.ts` | 口径 chip 标「（默认口径）」 |

## Verification（验证）

单句真链路（新会话、零上下文、零提问）：
「把最差的那个月的明细给我看看」→ 卡片 `status=complete`、`missing_fields=[]`、
`detail_level=detail`、`top_period={min, month, 销售额}` → 直接确认 →
v1 `done`，**200 行 × 4 列**（日期/区域/品类/销售额），SQL 带选定那一期的过滤条件。

## Explicitly NOT doing（不做事项）

- 不做「所有槽位都自动给默认值」：时间/范围可以默认，角度仍然只在**真的没给**时问一句；
- 不删掉选项能力（一词多义时仍需要），只是不再把「没提」当成「歧义」；
- 不在需求层加数据库探测来选默认口径（注册表 `default: true` 已经是唯一来源）。

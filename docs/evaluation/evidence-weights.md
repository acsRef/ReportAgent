# 证据分量（Evidence Weights）

> 同一句"跑通了"，在 Demo、PoC、测试环境、受限试行、正式运行里**不是一回事**。
> 这份表规定：每一档允许说什么、不许说什么，以及本项目的结论现在处于哪一档。

## 五档定义

| 档位 | 环境 | 允许的结论 | 禁止的结论 |
|---|---|---|---|
| **D1 Demo** | 本机、随时可变、数据可编 | "这个功能能演示" | 不能说通过率、稳定性、性能 |
| **D2 PoC** | 本机全栈 + 真数据，但**单次**运行 | "在这个版本、这批数据上，这条用例通过了" | 不能说"平均"、不能说"多数情况" |
| **D3 测试环境** | 固定 commit + 固定数据集 + 可重复跑 | "N 次运行、M 条用例，命中率 X%" | 不能推断线上流量、并发、越权 |
| **D4 受限试行** | 真实用户/真实数据、范围受限（如只读、只内网） | "在 X 范围内、Y 时段，观察到的指标是 Z" | 不能推广到全量用户 |
| **D5 正式运行** | 全量、7×24、有告警与回滚 | "线上 SLO 是 Z" | 不能拿"某次回归结果"冒充 SLO |

## 每档必带的四项

1. **环境**：`base_url`、数据是否入库、模型与 prompt 版本；
2. **版本**：代码 commit（平台每条运行记录都写）；
3. **覆盖层**：deterministic / gold 覆盖了哪些 check，哪些是 `deferred`；
4. **限制**：这份结论**不能**说明什么（例：只测了检索层，没测生成质量）。

## 本项目的现状归类

| 结论 | 档位 | 依据 |
|---|---|---|
| ReportAgent `execution_accuracy = 1.0`（10/10 金标） | **D3** | 固定 commit + 固定种子数据 + 金标 SQL 现跑；但样本 10 条，T3 只 1 条 |
| 记忆召回 R@1 0.84 / R@3 0.96（25 记忆 / 30 查询） | **D3** | 真 embedding，多次跑过（Jaccard 0.94~0.97） |
| ragent 65 题均分（LLM 裁判） | **D2** | 单次快照，裁判未逐题人工复核 |
| ragent 检索 `doc_hit@5`（平台实时跑） | **D3**（人工核验子集）/ **D2**（未核验题） | 取决于该题 `gold_source` |
| ReportAgent 需求卡字段一致率（平台实时跑） | **D2** | 单次运行，未做 N 次稳定性 |
| 压缩/崩溃恢复等专项 | **D2** | 真机实验，n=1~3 |

## 纪律

- **不许跨档发言**：D2 的结果不能说成"D3 平均"；D3 不能说成"D5 SLO"；
- **样本量要跟着数字走**：写"10/10"而不是"100%"，写"1 条 T3 用例"而不是"T3 全过"；
- **不可复算的快照只能当背景**：`eval_results.json` 是历史快照，登记档位为"仅参考"，不许拿它当 live 结论；
- **未覆盖要主动说**：`deferred` 的层不算通过，汇报时必须念那句"这几层没测"。

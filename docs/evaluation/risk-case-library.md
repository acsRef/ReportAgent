# 边界案例库（Risk Case Library）

> 来源：ReportAgent 的真实事故与 plan（精选 5 条）+ ragent 测试集里的题目元数据（`考察的RAG易错点`
> / `常见错误答案` / `gold_judgment`，平台自动派生）+ **评测工具自身事故 5 条（EV-R1…EV-R5，也进平台风险库）**。
> 平台「风险库」页按类别分组渲染，当前 **51 条**。

## 五类风险与判定办法

| 风险 | 典型表现 | 怎么测（可判定的方式） |
|---|---|---|
| **误答** | 口径被换（问销售额答净销售额）、时间范围丢失 | 金标结果比对（多重集 + 容差），不看文字像不像 |
| **幻觉** | 编造表名/列名；文档里没有的数值张口就来 | 表 allowlist + EXPLAIN；`gold_judgment=not_answerable` 的题必须拒答 |
| **越权** | 读到别人的会话 / 知识库 | owner 双条件查询；404 不区分「不存在/不是你的」 |
| **错误执行** | 过滤写进 `LEFT JOIN … ON`；NULL 分组当冠军 | 确定性契约闸（必需过滤必须在 WHERE；NULL 不进极值评选） |
| **不可追溯** | 崩了只有 `phase=generating`，现场全丢 | span 增量落盘 + 失败 kind + 三态落库（FAILED 也写一行） |

## ReportAgent（精选，来自真实事故）

| ID | 风险 | 场景 | 触发条件 | 现有护栏 |
|---|---|---|---|---|
| RA-R1 | 误答 | 「销售额」被解析成「净销售额」 | 候选排序按中文码点，`净` < `销` | 原话命中优先；夹具逐字取口径 |
| RA-R2 | 错误执行 | 过滤写进 `LEFT JOIN … ON` → 算出全库 9.38 亿（真值 3936 万） | 模型把 `region='华南'` 写进 ON 子句 | C1/C2 两道确定性契约闸 → 走 repair |
| RA-R3 | 不可追溯 | 强杀后端后 `last_failed_action` 为空、0 条版本行 | 内存缓冲 + 未收敛孤儿会话 | 启动孤儿收敛 + span 增量落盘 + `interrupted` 可重试 |
| RA-R4 | 幻觉 | 编造 `dim_supplier` / `sales_amount` | 模型自由生成 SQL | 6 层 SQL 安全闸（含表 allowlist + EXPLAIN） |

## 评测工具自身（2026-11-17 真实事故）

| ID | 风险 | 场景 | 触发条件 | 现有护栏 |
|---|---|---|---|---|
| EV-R1 | 错误执行（作用域过宽） | 平台清理临时库，把**全库 14 份文档 1391 chunks** 删了 | `GET /documents` 不支持 `kb_id` 过滤，admin 拿到全部；清理逻辑按列表逐个删 | `ragent_docs` 客户端过滤 + 回归测试；清理只作用于本库 document_id |

> 这条必须记：**评测工具自己也会造成事故**。它和生产代码一样需要"作用域断言"和"破坏性动作的 dry-run"。

| ID | 风险 | 场景 | 触发条件 | 现有护栏 |
|---|---|---|---|---|
| EV-R2 | 工具超时误报 | 上传后等 90s 判"入库失败" | PDF 走 OCR（250 页）+ 元数据 LLM 批处理，真实耗时分钟级；批量灌库时串行排队更久 | 等待上限 300s；超时记 `timeout`/`error` 而非 `fail`；文档写明"入库分钟级" |
| EV-R3 | 判定器自身的口径错（假失败） | 跨文档召回命中 2/3 被判 `fail` | 阈值写成 `ratio >= 0.67`，而 2/3 = 0.6666…，永远够不到；detail 文案却写"至少 2/3" | 阈值改用真分数 `CROSS_DOC_RECALL_MIN = 2/3` + 容差；回归测试 `test_recall_two_of_three_passes` 钉住 |
| EV-R4 | 资产缺陷（金标证据不成立） | Q11 问"主要会计数据表的金额单位"，金标证据关键词却是 `25,930`（员工人数） | 标注时把"命中同一份文档"当成"证据成立"；关键词与该问无因果关系 | 判定记录里保留 `expected/observed`，人工复核时能看出关键词与问题不对应；已知缺陷记在本节而不是改数据让它变绿 |
| EV-R5 | 提速开关的隐性代价（质量回退） | 为把入库从分钟级压到秒级，用 `INGEST_METADATA_ENABLED=0` 重灌三份年报 | 元数据 LLM 关闭后 `chunks.year` 全为 NULL → ragent 的 `period` / `coverage_by_year` / 跨年冲突检测退化为"不可比" | 平台量化：2025 年题（Q25）金标文档在 k≤12 完全不出现；文档/博客写明"检索可用但元数据加成缺失"，重灌必须显式选择档位 |

> EV-R3 值得单记一笔：**判定器有 bug 时，你看到的是"产品失败"**。8 条 fail 里有 4 条是阈值算错，
> 另外 4 条才是真问题。如果不逐条看 detail，就会得出"恢复后检索整体变差"的错误结论。

## ragent-py（自动派生）

平台按题目元数据派生，规则：

| 条件 | 归到哪类 |
|---|---|
| `gold_judgment == not_answerable` | 幻觉（应拒答） |
| 类别 `H-错误前提纠偏` | 错误前提（迎合性） |
| 类别 `I-拒答与知识边界` | 幻觉 / 知识边界 |
| 类别 `E-时序与追溯调整` | 口径矛盾（同一事实两个版本） |
| 类别 `F-口径与概念辨析` | 口径混淆（分母/费用化 vs 资本化） |
| 类别 `G-实体消歧` | 实体混淆（三一集团 vs 三一重工） |
| 类别 `D-计算与多跳推理` | 多跳算错 |
| 类别 `B-表格理解与单位换算` | 单位换算（千元 vs 亿元） |

当前自动派生 **≈35 条**（65 题中命中上述条件的），每条带「触发条件 = 该题 gold_evidence 的关键词」。

## 用法

1. 新功能上线前，先跑一遍对应类别的风险用例（不必全量）；
2. 线上发现新坑 → 加一条风险用例（标题写"用户看到的现象"，不写内部实现）；
3. 每条风险必须能回答：**触发条件 / 期望证据 / 现有护栏 / 关联用例 ID**——四缺一就是没沉淀。
